# V0.7 — Bounded SmartPass Candidate Search

## Goal
Implement a bounded, auditable candidate lifecycle around GCC builds and benchmark execution.

## Deliverables
- Candidate/configuration model.
- Explicit, whitelisted candidate space.
- Baselines always included.
- `nova tune <benchmark> --budget B` or documented equivalent.
- Safe process invocation with argument arrays; no shell-concatenated command.
- Build, correctness, benchmark, rank and report pipeline.
- Failure reason for every failed candidate.
- JSON/CSV output and `nova explain` or equivalent report command.
- Fixed and random search strategies for comparison.

## Candidate lifecycle
`GENERATED -> BUILD_FAILED | BUILT -> CORRECTNESS_FAILED | CORRECT -> BENCHMARKED -> ELIGIBLE/REJECTED_BY_POLICY`.

Candidates that fail to build or fail correctness must not be ranked as winners. A baseline remains visible even when it fails, with its failure reason.

## Required tests
- Budget B results in no more than B candidate evaluations according to documented accounting.
- Baseline inclusion policy is tested.
- Invalid flag/config is rejected before process execution.
- Build failure is recorded.
- Correctness failure is recorded and candidate is ineligible.
- Timeout is recorded if timeout support is implemented.
- Same seed and same configuration produce the same candidate sequence.
- Result files preserve raw samples and metadata.
- Winner selection is based only on eligible candidates.
- If no candidate is eligible, command exits non-zero and reports why.

## Verification loop
Use a small test benchmark; include a purposely failing candidate fixture; run fixed and random search under equal budget; inspect candidate table; rerun from the same seed; compare sequence and metadata.

## Pass conditions
- All lifecycle paths have tests.
- Budget enforcement is proven by test.
- Incorrect candidate cannot win.
- Failures are never silently dropped.
- Baseline and candidate records are complete.
- Full project suite passes.
- Evidence saved.

## Exit gate
Do not call the strategy adaptive until it uses workload descriptors or prior outcomes to choose future candidates.
