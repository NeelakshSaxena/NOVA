# V0.4 — Semantic Analysis, Symbol Table and TAC

## Goal
Reject semantically invalid programs and generate deterministic three-address code from valid ASTs.

## Language rules
- Initial values and arithmetic are integers.
- A variable must be declared before use.
- Duplicate declarations in the same scope are errors.
- Assignment requires a declared variable.
- Division behavior and divide-by-zero policy must be explicitly defined.
- No implicit scope, type or initialization rule may be left ambiguous.

## Deliverables
- Symbol table.
- Semantic analyzer with source-located diagnostics.
- TAC instruction representation and deterministic printer.
- `nova tac <file>` command.
- A reference evaluator/interpreter is recommended before optimizer work.

## Required tests
- Valid declaration, assignment and print.
- Use before declaration.
- Duplicate declaration.
- Assignment to unknown variable.
- Invalid expression if type rules later expand.
- TAC for arithmetic expression.
- Stable temporary numbering and stable output.
- Division edge cases according to declared semantics.

## Verification loop
Run semantic/TAC unit tests, invalid-program integration tests, full CTest, and golden TAC output checks. Compare interpreter result to expected result for small programs.

## Pass conditions
- Invalid programs fail before TAC generation or execution.
- Valid programs produce expected deterministic TAC.
- Diagnostics identify source location and issue.
- Language semantics are documented.
- Full previous gates remain green.
- Evidence recorded.

## Exit gate
No optimizer until semantic rules and TAC representation are stable.
