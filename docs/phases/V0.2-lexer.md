# V0.2 — Lexer

## Goal
Convert NOVA Script source text into a deterministic token stream with source locations and useful lexical errors.

## Language slice
Support only syntax defined here and in the current grammar. Initial token types: identifier, integer literal, `let`, `print`, `=`, `+`, `-`, `*`, `/`, `(`, `)`, `;`, end-of-file, and whitespace. Add comments only if explicitly implemented and tested. Do not silently accept unsupported syntax.

## Deliverables
- `TokenKind` enum class.
- `Token` structure with lexeme and start line/column (and end location if useful).
- Lexer class or function with clear input/output contract.
- Token dump command, e.g. `nova tokens examples/basic.nova`.
- Location-aware lexical diagnostics.
- Unit tests for all token classes.

## Required tests
- Empty input produces EOF.
- Whitespace between tokens.
- Identifier and keyword distinction (`letx` must not become `let` + `x`).
- Integer literal.
- Every punctuation/operator token.
- Multi-character invalid token/unknown character.
- Correct line/column after newlines and tabs according to documented tab policy.
- EOF location is deterministic.
- Long input does not crash or read out of bounds.

## Verification loop
1. Add tests before/with implementation.
2. Run lexer unit tests.
3. Run full CTest regression suite.
4. Run token dump on `examples/basic.nova`.
5. Run invalid-character example and verify non-zero exit plus location.
6. Inspect memory safety and bounds handling.
7. Save evidence and update status.

## Pass conditions
- All token kinds have tests.
- Lexemes and locations match expected values.
- Invalid characters are reported at the correct location.
- Existing V0.1 tests still pass.
- No unsupported token is falsely accepted.
- Evidence ledger updated.

## Exit gate
Do not start parser work until the lexer passes the full gate.
