# NOVA

NOVA has two separate parts, written in C++17 with CMake and used from a terminal:

1. **NOVA Script compiler** — an educational compiler for a tiny integer language: lexer, recursive-descent parser, AST,
   semantic analysis, three-address code (TAC), a four-pass optimizer, and reference interpreters.
2. **SmartPass** — an *experiment controller* that asks **GCC** to compile fixed C++ numerical kernels with a whitelisted set
   of flag configurations, validates every result against an independent oracle, times the survivors with a documented
   protocol, and compares search strategies (fixed, random, adaptive) under equal evaluation budgets.

NOVA does **not** compile C++ itself and does not replace GCC. The two parts share no code paths in the measurements.

**Status: V1.0 `RELEASED` for the verified configuration** (Windows 11, MinGW.org GCC 6.3.0): everything below is implemented
and tested; sanitizers could not be run on this toolchain and other platforms are unverified. See
[docs/RELEASE.md](docs/RELEASE.md) for the checklist with evidence and [Known limitations](#known-limitations).

## Build and test

Requires CMake >= 3.16 and a C++17 compiler (verified with CMake 4.4.4 and MinGW.org GCC 6.3.0 on Windows 11);
Python 3 (standard library only) for the report tests.

```
cmake -S . -B build                 # on Windows/MinGW add: -G "MinGW Makefiles"  (and put C:\MinGW\bin on PATH)
cmake --build build
ctest --test-dir build --output-on-failure
```
`scripts/verify_phase.sh <phase>` performs a clean configure/build/CTest and logs it under `state/evidence/<phase>/`.
The full suite takes several minutes because the integration tests compile and run real kernels.

## NOVA Script: commands and language

| Command | Behavior |
|---|---|
| `nova tokens <file>` | token stream with line:column; lexical errors exit 1 |
| `nova ast <file>` | syntax tree; syntax errors (first one, with location) exit 1 |
| `nova tac <file>` | semantic check (declare-before-use, duplicates) then three-address code |
| `nova run <file>` | execute with the reference interpreter; division by zero is a located runtime error (exit 1) |
| `nova opt <file> [--passes=fold,propagate,simplify,dce] [--show-all]` | optimize the TAC to a fixed point |

Example (`examples/basic.nova`): `let x = 10; let y = 20; let z = x * 2 + y; print z;` — see [docs/DEMO.md](docs/DEMO.md)
for real transcripts of every command. Language: [docs/grammar.md](docs/grammar.md), [docs/language.md](docs/language.md)
(64-bit wrapping integers, truncating division); optimizer: [docs/optimizer.md](docs/optimizer.md).
Exit codes: 0 success, 1 input/runtime error, 2 usage error.

## SmartPass and the benchmark lab

| Command | Behavior |
|---|---|
| `nova bench list` / `run` / `report <dir>` | build -O2/-O3 baselines of the kernels, validate, time, save raw samples ([docs/benchmarks.md](docs/benchmarks.md)) |
| `nova tune <benchmark> --budget=B [--strategy=fixed, random or adaptive]` | bounded search over whitelisted GCC flags with a correctness gate ([docs/smartpass.md](docs/smartpass.md), [docs/adaptive.md](docs/adaptive.md)) |
| `nova explain <dir>` | every candidate, its lifecycle state, failure reason, and the winner |
| `nova evaluate <tune-dir>` | re-measure a finished selection on holdout sizes (never feeds back into a selection) |
| `nova table <benchmark>` | measure every configuration on given sizes (ground truth for studies) |
| `nova study --tables=... --out=...` | replay strategies against saved tables, with leakage rules |
| `nova history --tables=... --out=FILE` | tuning-size history file for the adaptive policy |

Kernels: `matmul`, `vector_add`, `stencil` (`benchmarks/kernels/`). Saved raw data and manifests: `benchmarks/results/`.

## Results and report

[report/report.md](report/report.md) is generated by `python scripts/make_report.py` from the saved raw data only; every value is
traced in `report/traceability.json`. It evaluates five hypotheses with a fixed decision rule; in the measured setting the adaptive
policy beat random search at small budgets (H1, H2 supported), the contribution of its individual signals is inconclusive (H3 to
H5), and all methods tie at an exhaustive budget. The report states what these data do not show; read its sections 10 and 11
before quoting any number.

## Repository map

- `src/`, `include/nova/` — compiler (`lexer`, `parser`, `semantic`, `tac`, `interp`, `optimizer`), `bench/` (process runner, oracle, harness), `tune/` (space, policy, tuner, study).
- `tests/` — unit and integration tests (CTest), fixtures with deliberately broken kernels; `scripts/mutation_check.py` + `scripts/mutations/` prove the tests can fail.
- `docs/` — specifications and per-component documentation; `docs/phases/` — the phase gates.
- `state/` — roadmap, verification ledger, decisions, known issues, phase log, and `state/evidence/<phase>/` logs of actual runs.
- `AGENTS.md`, `.claude/CLAUDE.md` — the engineering contract this repository was built under.

## Known limitations

- Only MinGW.org GCC 6.3.0 (32-bit x86 target) on Windows 11 was available: results say nothing about newer GCC or other machines;
  the POSIX process runner is written but has never been compiled or run.
- No AddressSanitizer/UBSan on this toolchain; tests were additionally run with checked standard-library containers.
- Three small kernels, one machine, timing pinned to one logical CPU; the adaptive policy's constants were written after the author had
  seen earlier timings of the same kernels.
- The directory is not a git repository; there is no commit history to cite.
- Full list: [state/KNOWN_ISSUES.md](state/KNOWN_ISSUES.md).
